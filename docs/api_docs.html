news-scraper API

v1.1.0 — Scraping news · Dashboard su /ui/

Panoramica

Il microservizio espone endpoint REST per l'estrazione di notizie tramite Playwright. È ottimizzato per restituire testo pulito pronto per l'elaborazione da parte di modelli LLM.

Autenticazione API (scraping): Se API_AUTH_TOKEN è configurato, tutti gli endpoint /scrape* richiedono:

Authorization: Bearer <API_AUTH_TOKEN>

Configurazione LLM: Le chiamate all'LLM usono HTTP POST diretto all'endpoint OpenAI-compatible (LLM_BASE_URL/chat/completions). Supporta Ollama, LM Studio, e qualsiasi endpoint compatibile OpenAI.

Verifica lo stato di salute del servizio.

Risposta:

Dashboard Web (NiceGUI)

GET /login

Pagina di login per la dashboard. Restituisce HTML self-contained con form password.

POST /auth/login

Autentica con password e imposta il cookie di sessione news_scraper_ui (HttpOnly, SameSite=Strict, TTL 7 giorni).

Body (form-data):

CampoTipoDescrizione
passwordStringPassword configurata con scripts/set_password.py

Risposte:

StatusBodyDescrizione
200{"ok": true}Login riuscito, cookie settato
401{"detail": "..."}Password non valida o non configurata
429{"detail": "..."}Rate limit (5 tentativi/IP per 5 min, 20 globali/min)

GET /auth/logout

Elimina il cookie di sessione e reindirizza a /login.

GET /ui/ Cookie

Dashboard NiceGUI — metriche delle ultime 24h: totale richieste, OK/Errori, durata media, token LLM prompt/completion. Storico degli ultimi 50 request. Auto-refresh configurabile (REFRESH_ENABLED/REFRESH_INTERVAL, default 30s).

Richiede cookie news_scraper_ui. Redirect a /login se assente o scaduto.

GET /ui/config Cookie

Editor configurazione con hot reload. Modifica LLM (base URL, API key, modello, temperature, timeout, max prompt chars), Scraping (timeout, debug mode), Interfaccia (auto-refresh), API (rate limit, auth token).

Le modifiche sono scritte direttamente in .env ed effettive entro ~5s (hot-reload), RATE_LIMIT incluso.

Dettagli Tecnici

  • LLM integration: HTTP POST diretto a {LLM_BASE_URL}/chat/completions via httpx. Schema payload OpenAI-compatible con response_format: json_object.
  • Smart Scraping: Playwright → BeautifulSoup (normalizzazione) → MarkItDown (HTML→Markdown) → LLM (estrazione strutturata).
  • Hot reload config: .env è l'unica fonte di configurazione. La UI scrive le modifiche direttamente in .env; un task in background rilegge il file ogni 5s e applica i cambi (anche se editato a mano). I parametri LLM sono letti dal ConfigManager ad ogni chiamata (client httpx creato per richiesta), quindi le modifiche sono attive immediatamente.
  • Metriche: SQLite (data/metrics.db) — ogni request registra endpoint, URL, status, durata, token LLM prompt/completion.
  • Auth dashboard: Password hashed con scrypt (n=16384). Token JWT cookie HttpOnly. Rate limit: 5 tentativi/IP per 5 min, 20 globali/60s.
  • Timeout: SCRAPE_TIMEOUT configura il timeout globale. Al superamento: HTTP 504.
  • Rate limiting: RATE_LIMIT per IP. Riconosce CF-Connecting-IP, X-Real-IP, X-Forwarded-For.
  • Validazione URL: Solo http/https. Blocca IP privati/loopback (SSRF guard) — risponde HTTP 422.
  • Concorrenza: Max 3 browser Playwright simultanei (semaforo).
